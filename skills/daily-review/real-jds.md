## 二、共性分析（基于上述 ~20 个有详情 JD）

### A. ≥ 80% JD 出现的"必备硬技能"

| 技能 | 出现频率 | 备注 |
|---|---|---|
| **Python 精通** | ~95% | 几乎所有 JD 第一硬指标；少量补充 Go/Java/TS |
| **LLM API + Prompt Engineering** | ~95% | 国内国外通用；国外强调 "production"，国内强调"熟练运用" |
| **RAG 构建经验** | ~85% | 国内 JD 经常具名"Graph RAG"、"向量化"、"多源数据融合" |
| **Agent 框架使用**（LangChain / LangGraph / AutoGen / MCP 任一） | ~85% | 腾讯、阿里、字节、Anthropic、Cursor 都明确列名 |
| **评测体系 / Eval 框架** | ~80% | Anthropic / Cursor 几乎每个 JD 都列；国内 JD 也越来越多 |
| **生产环境部署经验** | ~80% | 国内强调"工程化落地"、国外强调"production / deployment at scale" |

### B. 50-80% 出现的"高频加分"

| 技能 | 频率 | 备注 |
|---|---|---|
| **Function Calling / Tool Use 设计** | ~70% | 显隐性都有，Anthropic / Cursor 显性，国内通过"Agent 框架"隐含 |
| **Multi-Agent 协作 / Planning** | ~65% | 腾讯、阿里、Cursor、Perplexity、小红书均出现 |
| **Docker / K8s** | ~60% | 国内 JD 出现频率显著高于外企 |
| **微调（LoRA / SFT / RLHF）** | ~55% | 国内大厂高频；外企 Anthropic 主要在 prompt 而非微调 |
| **A/B 测试与灰度** | ~50% | 国内 Cursor / OpenAI / 字节产品向岗位高频 |
| **Dify / Coze 等低代码 Agent 平台** | ~50% | 国内特有（腾讯 ADP 显性列出 Dify） |
| **Java / Go 后端** | ~50% | 国内 Agent 工程化岗常要求；外企较少 |

### C. < 50% 的"差异化加分"

- **MCP（Model Context Protocol）** — 仅腾讯广告、Anthropic 显性列出，但快速上升趋势
- **强化学习 / Planning algorithm** — 腾讯广告、Anthropic、Cursor research 类
- **AI Safety / Alignment / Constitutional AI** — Anthropic 强；国内 JD 几乎不写
- **开源贡献** — 腾讯、Anthropic、Cursor 明确列；国内大厂普遍仅当加分
- **Cost-aware 设计** — Cursor 的 "Auto 模型选择" 是显性能力；国内只通过"工程化"模糊表达
- **可观测性 / APM / Prometheus** — 腾讯 ADP 显性，其他仅 infra 岗
- **多模态（图 / 视频 / 语音）** — 偏向通用模型团队，应用工程岗较少
- **PyTorch 微调 / 分布式训练** — 偏向算法岗（美团北斗、字节 Seed），应用工程岗已经弱化

### D. 国内 vs 外企的核心差异

| 维度 | 国内大厂 | 海外 / 外企 |
|---|---|---|
| **学历门槛** | 985 硕士强偏好（美团 / 蚂蚁 / 阿里 Tongyi 显性），本科可投但弱 | 明确弱化学历，强调"shipping" |
| **Java/Go 后端** | 常要求，因为是中台 / 微服务文化 | 几乎不提，Python + TS 为主 |
| **算法 vs 应用边界** | 偏模糊，常合并为"大模型应用算法工程师" | 清晰：Applied AI / FDE / Product / Research 各自 ladder |
| **Dify / Coze 等本土平台** | 高频出现 | 不出现 |
| **MCP / Agent SDK** | 仅腾讯、字节少数岗位 | Anthropic / Cursor / Perplexity 已是默认词 |
| **客户面向（FDE）** | 蚂蚁、阿里云、腾讯云有但弱称呼 | OpenAI / Anthropic 已经是热门独立 ladder |
| **薪资透明度** | BOSS 直聘有；官网无 | Greenhouse JD 多数明确公开 base |
| **明确 1-2 年门槛的 JD 比例** | 高（社招分类清晰） | 低（多数 3+ 年；Google "2+ 年"、OpenAI Emerging Talent "0-3 年"是少数明确友好的） |

### E. 1 年经验最容易卡住的要求

1. **"3 年以上"经验门槛** — 腾讯混元 Agent、Anthropic 多数 Applied AI、OpenAI FDE 都是 3+；1 年要靠项目硬证拉平
2. **"production / 上线规模"** — 国外 JD 几乎都要 "deployment at scale"；1 年人通常只有 demo / 内部工具
3. **985 硕士偏好** — 美团、蚂蚁、阿里通义算法岗的隐形门槛；本科 1 年很容易被前置筛掉
4. **完整 Eval 体系构建经验** — Anthropic / Cursor 几乎所有岗都要求；1 年人通常只做过手工评测
5. **Multi-Agent 系统**真实落地 — 公开课能讲明白，但有线上落地的 1 年开发者很少
6. **Go / Java 后端 + Python AI 双栈** — 国内 Agent 工程化岗要求，纯 Python 背景难达标

### F. 隐形门槛（写"加分项"但实际近 100% 通过者都有）

1. **GitHub 上有公开 Agent / RAG 项目** — Anthropic、Cursor、字节 Seed 几乎所有 hire 都有；JD 只写"加分"
2. **能阅读并复述近 1 年的核心 paper**（ReAct / Reflexion / Constitutional AI / MCP / Agent S） — 外企面试隐性要求
3. **对 Claude Code / Cursor / Devin 有深度使用**，能讲出与自己代码风格的优劣对比 — Anthropic、Cursor 面试高频隐性问题
4. **英文技术写作 + 异步沟通**（Notion / Linear / GitHub Issue 风格）— 所有外企默认要求
5. **成本敏感**（能讲出"我把 X 场景成本从 ¥A 降到 ¥B"具体数字） — 国内大厂 staff 评审标准、外企 product 岗隐性指标
6. **开源贡献到主流仓库的 commit / PR** — Anthropic 招"Beneficial Deployments"、Hugging Face DevRel 几乎必备

## 三、role-rubric.md 修订建议

> 基于上述 ~20 个真实 JD 与 daily-review 当前 rubric 比对。

### A. 建议**新增**的条目（真实 JD 高频但 rubric 缺）

1. **A2 新增：MCP（Model Context Protocol）理解与使用** — 在 Anthropic / 腾讯广告 / 已成默认词；rubric 里只字未提
2. **A2 新增：Agent SDK / Agent harness 概念**（Cursor 显性、Anthropic 显性） — rubric 现在只列"Claude Agent SDK"作为框架名，需上升为"理解 agent loop / tools / context management 的设计"
3. **A4 新增：Tool use 安全设计**（least privilege、sandboxed execution） — Anthropic 面试明确要点
4. **A5 新增：Offline replay / Curated dataset / LLM-as-judge** — Cursor / Anthropic 显性，rubric 现在只笼统说"Eval 集设计"
5. **A5 新增：用户信号收集 + 反馈闭环**（feedback loop from real usage） — Cursor 显性
6. **B2 新增：Workflow 引擎 / 插件系统设计** — 腾讯 ADP / 字节 Coze 后台开发岗常考
7. **C 新增：客户面向能力 / FDE 思维**（白手套交付、把模糊需求转成 PoC） — OpenAI / Anthropic 显性 ladder
8. **D 新增：技术内容写作**（blog、教程、demo）— Anthropic Beneficial Deployments JD 显性列出
9. **D 新增：对前沿模型有"taste"** — Cursor 显性 "informed perspective on model and agent behaviors"

### B. 建议**删除或降权**的条目（rubric 写了但真实 JD 极少）

1. **A1 "Prompt Caching 等成本优化机制"** — 真实 JD 几乎不写；移至 D 加分项（"Cost-aware 设计"已涵盖）
2. **A3 "HyDE / Query Rewriting"** — 国内国外 JD 都几乎不显性提；可合并到"检索策略"一项
3. **A3 "多模态 RAG"** — 出现率 < 20%，对纯应用工程岗权重过高；建议降权或归入加分
4. **A4 "Self-reflection / Self-correction / Critique"** — JD 几乎不显性写（仅 Anthropic / Cursor 隐含）；降权到加分
5. **C "找业务痛点的能力（用户访谈）"** — 国内 JD 几乎不要求开发者做用户访谈；降权（更属于 PM 边界）
6. **C "英文论文阅读"** — 国内大厂 1-2 年岗并不显性要求；建议合并到 D 加分项（外企必备 / 国内加分）
7. **D "论文积累：复述 ReAct / Reflexion ..."** — 1-2 年应用工程岗 JD 不写；保留但降权

### C. 应**调整描述**（更贴 JD 用语）的条目

1. **A2 "LangChain / LlamaIndex 至少一个"** → 改为 **"LangChain / LangGraph / AutoGen / Dify / Coze 任一深度，且能讲出 Agent loop 内部机制"**（贴近腾讯、字节、Cursor 原文）
2. **A2 "Function Calling / Tool Use 设计"** → 加上 **"含工具权限设计与失败回退"**（贴近 Anthropic）
3. **A4 "Memory 设计"** → 加 **"工程化 memory：Redis / 向量库 + TTL / 召回策略"**（国内工程岗显性）
4. **A4 "Cost / Latency 优化"** → 加 **"小模型分流 / 模型自动选择（Auto 模式）"**（Cursor 原文）
5. **A5 "回归测试 / A/B / 灰度"** → 加 **"百万级用户在线 A/B"**（Cursor / 字节产品向岗）
6. **B1 "FastAPI / Flask"** → 加 **"或工作流引擎 + 插件系统"**（腾讯 ADP）
7. **B2 "Docker / K8s 基础"** → 升为 **"K8s（含 Helm chart）+ 成本控制"**（腾讯 ADP 原文）
8. **D "GitHub 开源贡献"** → 升级措辞为 **"主流仓库（LangChain / Dify / transformers）的 PR 或独立项目带 100+ star"**（贴近 Anthropic / Cursor 实际隐形门槛）

### D. 优先级建议（1 年经验 → 大厂社招的关键卡点 Top）

排序后的"必须先补"清单（高 → 低）：

1. **真实上线的 Agent 项目** — 必须能拿出用户级 / 内部生产级的 demo + 数据，而非纯 toy（卡掉 80% 的 1 年候选人）
2. **Eval 体系建设经验** — Anthropic / Cursor / 字节都问；用 Curated dataset + scorer + dashboard 闭环讲一遍
3. **LangChain / LangGraph / AutoGen 至少一个的内部机制讲清** — 不仅会用 API，能讲 Agent loop 怎么决策
4. **生产成本数字** — "我把单次 query 成本从 X 降到 Y" 这类硬数字
5. **MCP / Tool 使用安全设计** — 上升期热词，提前掌握能在外企面试拉开差距
6. **后端工程化基本功**（K8s / 微服务 / 监控） — 国内大厂应用岗硬要求；纯前端 / 算法转过来最容易被刷
7. **985 硕士 / 论文积累的替代品** — 没学历就需要：开源 PR、技术博客阅读量、行业演讲；任一项需 1 项以上
8. **英文写作 + Notion/Linear 异步工作风格** — 外企门槛；可通过持续在 GitHub Issue / Discord 公开互动累积
